# AI.Image.Material.Collaboration.Platform 软件需求模型

## 1. 系统概述

AI.Image.Material.Collaboration.Platform（FishPics）是一个高颜值、功能完善的图片分享与互动社区平台，基于前后端分离架构设计。平台支持用户注册登录、图片浏览管理、帖子发布评论、后台审核管理等核心功能，致力于打造简洁高效、安全可靠的图片内容生态。

### 1.1 项目目标
- 提供美观流畅的用户体验（PC/移动端自适应）
- 构建完整的图片生态系统
- 实现安全可靠的用户体系
- 保证高性能架构

### 1.2 技术架构
- **前端**: React 19 + Vite + Ant Design 6 + React Router v7 + Context API + Axios
- **后端**: Spring Boot 2.7.6 + MyBatis-Plus 3.5.15 + MySQL 8 + Redis + Knife4j + Hutool + Lombok

## 2. 功能需求分析

### 2.1 核心功能模块

#### 2.1.1 用户管理模块
- 用户注册（图形验证码验证）
- 用户登录（图形验证码验证，Redis存储Token）
- 密码加密存储（MD5 + 盐值）
- 权限控制（普通用户、管理员）
- 用户状态管理（正常、禁用）
- 退出登录
- 暗色模式切换

#### 2.1.2 图片管理模块
- 图片上传与存储
- 图片信息管理（名称、URL、尺寸、大小）
- 图片状态管理（正常、禁用、待审核）

#### 2.1.3 帖子管理模块
- 帖子创建（标题、内容、关联图片）
- 帖子展示与浏览
- 帖子状态管理（正常、禁用、待审核、逻辑删除）

#### 2.1.4 互动功能模块
- 评论功能（对帖子进行评论）
- 评论状态管理（正常、禁用、待审核）

#### 2.1.5 后台管理模块
- 用户管理（查询、编辑、封禁/解封）
- 分页查询用户列表
- 多维度搜索（ID、用户名、手机号、昵称、角色、状态）
- 管理员权限控制
- API文档自动生成（Knife4j）

## 3. 数据模型分析

### 3.1 实体关系图 (ERD)

系统包含四个核心实体：
- **User** (用户表)
- **Picture** (图片表)
- **Post** (帖子表)
- **Comment** (评论表)

**关系说明**:
- 一个用户可以拥有多个图片 (1:N)
- 一个用户可以发布多个帖子 (1:N)
- 一个用户可以发表多个评论 (1:N)
- 一个帖子可以包含多个图片 (1:N，通过pictureIds字段存储图片ID数组)
- 一个帖子可以有多个评论 (1:N)

### 3.2 数据库表结构

#### User 表
| 字段 | 类型 | 描述 |
|------|------|------|
| id | bigint | 用户ID (主键) |
| username | varchar(32) | 用户名（登录用）|
| password | varchar(128) | 密码 |
| avatar | varchar(256) | 头像URL |
| email | varchar(64) | 邮箱 |
| phone | varchar(16) | 手机号 |
| nickname | varchar(32) | 昵称（展示用）|
| status | tinyint | 状态 (1-正常, 0-禁用, 2-待审核) |
| delete | tinyint | 逻辑删除标记 (0-未删除, 1-已删除) |
| role | varchar(32) | 用户权限 (默认'user') |

#### Picture 表
| 字段 | 类型 | 描述 |
|------|------|------|
| id | bigint | 主键 |
| user_id | bigint | 用户ID (外键) |
| picture_name | bigint | 图片名称 |
| url | varchar(512) | 图片地址 |
| width | varchar(32) | 宽度 |
| height | varchar(32) | 高度 |
| size | varchar(32) | 大小 |
| status | tinyint | 状态 (1-正常, 0-禁用, 2-待审核) |

#### Post 表
| 字段 | 类型 | 描述 |
|------|------|------|
| id | bigint | 主键 |
| user_id | bigint | 用户ID (外键) |
| title | varchar(256) | 标题 |
| content | text | 内容 |
| picture_ids | varchar(512) | 图片ID数组 |
| status | tinyint | 状态 (1-正常, 0-禁用, 2-待审核) |
| delete | tinyint | 逻辑删除标记 |

#### Comment 表
| 字段 | 类型 | 描述 |
|------|------|------|
| id | bigint | 主键 |
| user_id | bigint | 用户ID (外键) |
| post_id | bigint | 帖子ID (外键) |
| content | text | 评论内容 |
| status | tinyint | 状态 (1-正常, 0-禁用, 2-待审核) |

## 4. 非功能性需求

### 4.1 性能需求
- 响应时间：页面加载时间 ≤ 2秒
- 并发用户：支持1000+并发用户
- 图片上传：支持大文件上传（≤50MB）

### 4.2 安全需求
- 用户认证：基于Token的认证机制（Redis存储登录状态）
- 数据安全：密码MD5加密存储（加盐：fish）
- 权限控制：基于角色的访问控制（user/admin）
- 内容审核：敏感内容过滤
- 图形验证码：防止暴力破解
- 跨域配置：CORS支持

### 4.3 可用性需求
- 系统可用性：99.9%
- 移动端适配：响应式设计
- 用户体验：直观易用的界面

### 4.4 可维护性需求
- 模块化设计：前后端分离
- 日志记录：完整的操作日志
- 监控告警：系统健康监控

## 6. 业务规则

### 6.1 用户相关规则
- 用户名长度：6-11个字符
- 密码长度：8-20个字符
- 密码确认必须与密码一致
- 用户名必须唯一
- 新用户默认昵称为：小鱼籽_ + 随机字符串
- 新用户默认角色为：user（普通用户）
- 管理员可修改用户状态（封禁/解封）

### 6.2 内容相关规则
- 帖子必须包含标题和内容
- 图片必须关联到用户
- 评论必须关联到帖子和用户
- 所有内容默认需要审核

### 6.3 权限相关规则
- 普通用户只能管理自己的内容
- 管理员可以管理所有内容
- 删除操作为逻辑删除
- 管理员不能封禁自己

### 6.4 验证码规则
- 验证码长度：5位
- 验证码有效期：5分钟
- 验证码存储：Redis
- 验证码类型：圆圈图形验证码
